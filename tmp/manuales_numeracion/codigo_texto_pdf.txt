1 Presentación del sistema 
Este manual explica la implementación de las mismas opciones del manual de usuario. Está dirigido 
a quien mantiene el sistema y necesita localizar sus componentes, validaciones, reglas y 
operaciones de datos. Cada opción conserva su pantalla y la relaciona con capturas reales del 
código y una explicación técnica breve. 
Las pantallas se reutilizan del manual de usuario con sus datos de demostración. Las imágenes de 
código se obtuvieron de los archivos actuales abiertos en Visual Studio Code Server desde el 
navegador integrado, sin recrear un editor. Los nombres de funciones y las líneas corresponden a 
esa revisión; una modificación posterior puede desplazar su ubicación. 
Arquitectura y responsabilidades 
La interfaz React y TypeScript se compila con Vite. El estado de trabajo y los contratos HTTP 
conectan los componentes con una API Express en Node.js. Las rutas validan entradas con Zod; los 
servicios coordinan reglas y transacciones; los repositorios ejecutan SQL parametrizado. El 
adaptador Node inicia un trabajador PowerShell y utiliza System.Data.SqlClient para SQL Server. La 
lógica analítica consulta una base dimensional distinta del OLTP. 
Capa Archivos y responsabilidad 
Interfaz src/LiveApp.tsx, src/pages y src/features componen las pantallas y sus acciones. 
Estado y contrato src/state/Workspace.tsx y src/api.ts mantienen la selección y las peticiones HTTP. 
API server/app.mjs y routes.mjs de cada dominio validan y publican las operaciones. 
Negocio service.mjs coordina reglas, autorizaciones, evidencias y transacciones. 
Persistencia repository.mjs, server/db.mjs y server/sql-worker.ps1 ejecutan las consultas. 
Integraciones server/integrations y server/agent separan recepción, análisis, despacho y confirmación. 
Análisis server/datamart, server/kpis y sql separan ETL, hechos dimensionales y tasas. 
 
Requisitos y configuración 
El README requiere Windows, Node.js 20 o superior, PowerShell con .NET, sqlcmd y SQL Server. 
package.json define npm install, npm run build y npm start para preparar y ejecutar la aplicación. 
npm run server y npm run dev separan API y Vite durante el desarrollo. npm run migrate aplica las 
migraciones del OLTP, incluido el acceso del administrador, las reglas del agente y los documentos 
de Conocimiento; npm run knowledge:init carga los documentos iniciales. npm run up inicia la API 
junto con el túnel público usado por los webhooks. El esquema OLTP reside en 
script/LaPreDigital_OLTP.sql; la creación y actualización del Data Mart se coordinan con las 
herramientas de tools/datamart.mjs. 
 
5 
La configuración de ejemplo está en .env.example. DB_SERVER y DB_DATABASE identifican el 
OLTP; DATAMART_DATABASE selecciona la base analítica. OPENAI_API_KEY y 
OPENAI_MODEL configuran el modelo principal; OLLAMA_ENABLED, OLLAMA_URL y 
OLLAMA_MODEL, el respaldo local. Los nombres de configuración de SMTP, Telegram, WhatsApp 
y Stripe se consultan en sus adaptadores. Este manual no incluye valores de claves, contraseñas ni 
tokens operativos. No se requiere exponer el editor o las bases mediante un túnel para consultar el 
código.

Implementación authenticate busca al administrador y compara la contraseña con su hash; si falta

/api/bootstrap después de iniciar sesión. Workspace mantiene luego los datos iniciales, la selección 
y los estados de carga y error.

persistencia

GET /api/kpis devuelve el origen dimensional y los resultados con los filtros

denominador debe mostrarse como No aplicable.

dimensional

Contratación y 
entrega
